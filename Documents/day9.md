# Day 9 – React + WebSocket Integration

## 1. Goal

Connect the React frontend to the Node.js WebSocket backend and receive real-time events generated by the C++ multithreading engine.

The complete data flow:

```text
C++ Engine
    ↓
Node.js Backend
    ↓
WebSocket Server
    ↓
React Frontend
    ↓
Dashboard UI
```

## 2. What is WebSocket?

WebSocket is a communication protocol that creates a persistent, two-way connection between a client and a server.

Unlike ordinary HTTP requests, the server can send data to the client whenever an event occurs, without waiting for another request.

**In ThreadScope:** The backend sends thread events to React as soon as the C++ engine generates them.

## 3. Creating a WebSocket Connection in React

We use the browser's built-in `WebSocket` API.

```jsx
const socket = new WebSocket("ws://localhost:8080");
```

- `ws://` – WebSocket protocol.
- `localhost` – our local machine.
- `8080` – backend WebSocket server port.

## 4. Important WebSocket Events

```jsx
socket.onopen = () => {
  console.log("Connected!");
};

socket.onmessage = (message) => {
  console.log(message.data);
};

socket.onerror = () => {
  console.log("Connection error");
};

socket.onclose = () => {
  console.log("Disconnected");
};
```

| Event | Meaning |
|---|---|
| `onopen` | Connection successfully established |
| `onmessage` | Data received from server |
| `onerror` | Connection error occurred |
| `onclose` | Connection closed |

## 5. React useEffect

We use `useEffect()` to establish the WebSocket connection when the component loads.

```jsx
useEffect(() => {
  const socket = new WebSocket("ws://localhost:8080");

  socket.onmessage = (message) => {
    const event = JSON.parse(message.data);
    console.log(event);
  };

  return () => socket.close();
}, []);
```

The empty dependency array `[]` means the effect runs when the component mounts.

The cleanup function closes the connection when the component unmounts.

## 6. Understanding JSON.parse()

The backend sends JSON data as a string.

Example:

```json
{
  "threadId": 1,
  "eventType": "START",
  "timestamp": 0
}
```

React receives the message as a string, so we convert it into a JavaScript object:

```jsx
const event = JSON.parse(message.data);
```

Now we can access its properties:

```jsx
event.threadId
event.eventType
event.timestamp
```

## 7. Updating React State

We use `useState()` to store incoming events.

```jsx
const [events, setEvents] = useState([]);

socket.onmessage = (message) => {
  const event = JSON.parse(message.data);

  setEvents((previousEvents) => [
    ...previousEvents,
    event
  ]);
};
```

The previous state is preserved, and the new event is appended to the array.

**Why use the callback form?**

`setEvents(previousEvents => ...)` ensures we update from the latest state instead of relying on a potentially outdated value.

## 8. Backend: Preventing Duplicate Engine Starts

Initially, the C++ engine was started inside every WebSocket connection handler.

This could launch multiple engine processes when multiple clients connected.

We fixed this using:

```js
let engineStarted = false;

function startEngine() {
  if (engineStarted) {
    console.log("C++ Engine already started. Skipping...");
    return;
  }

  engineStarted = true;

  // Start C++ engine
}
```

This ensures the engine starts only once during the backend process's lifetime.
